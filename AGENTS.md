# Предпочтения пользователя по интерфейсу

- Не добавлять постоянные пояснения, обучающие тексты и подсказки под полями, в выпадающих списках или виджетах: пользователь знает свою систему.
- Если пояснение действительно нужно, использовать только тултип при наведении.
- Это правило относится к поясняющим текстам; названия полей, данные операций и сообщения об ошибках сохранять.

- Для мобильных и планшетных интерфейсов обязательно соблюдать [правила безопасных областей](docs/mobile-layout.md). Фон/страница доходят до края, отступ получают поля, кнопки и панели управления. Использовать общие safe-area токены, не фиксированную высоту индикатора iPhone. Проверять геометрию с ненулевыми инсетами и экранной клавиатурой.

- Не переносить на вторую строку то, что помещается в одну. Не дублировать очевидные действия подписями. Содержимое сообщения важнее служебного оформления.
- На смартфоне просмотр фото управляется жестами: без панели «плюс / сброс / минус» и декоративных рамок вокруг фото. Не показывать рамку фокуса после касания или автоматического открытия окна; сохранять видимый фокус при навигации с клавиатуры.
- Для UI доступны пользовательские скиллы `frontend-design` (Anthropic), `ui-ux-pro-max` и `impeccable` в `~/.codex/skills`. Выбирать нужный этап: создание интерфейса, точечная проверка структуры/взаимодействия, визуальная доводка. Для мелкой правки читать только относящиеся к ней разделы, сохранять существующие токены и стиль INDEX12. Не генерировать заново дизайн-систему для локальной правки.
- Перед завершением UI-правки смотреть отрисованный результат и проверять касания отдельно от мыши и клавиатуры. Проверка только сборки не подтверждает качество интерфейса.

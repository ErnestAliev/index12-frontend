# Предпочтения пользователя по интерфейсу

- Не добавлять постоянные пояснения, обучающие тексты и подсказки под полями, в выпадающих списках или виджетах: пользователь знает свою систему.
- Если пояснение действительно нужно, использовать только тултип при наведении.
- Это правило относится к поясняющим текстам; названия полей, данные операций и сообщения об ошибках сохранять.

- Для мобильных и планшетных интерфейсов обязательно соблюдать [правила безопасных областей](docs/mobile-layout.md). Фон/страница доходят до края, отступ получают поля, кнопки и панели управления. Использовать общие safe-area токены, не фиксированную высоту индикатора iPhone. Проверять геометрию с ненулевыми инсетами и экранной клавиатурой.

- Не переносить на вторую строку то, что помещается в одну. Не дублировать очевидные действия подписями. Содержимое сообщения важнее служебного оформления.
- На смартфоне просмотр фото управляется жестами: без панели «плюс / сброс / минус» и декоративных рамок вокруг фото. Не показывать рамку фокуса после касания или автоматического открытия окна; сохранять видимый фокус при навигации с клавиатуры.
- Для UI доступны пользовательские скиллы `frontend-design` (Anthropic), `ui-ux-pro-max` и `impeccable` в `~/.codex/skills`. Выбирать нужный этап: создание интерфейса, точечная проверка структуры/взаимодействия, визуальная доводка. Для мелкой правки читать только относящиеся к ней разделы, сохранять существующие токены и стиль INDEX12. Не генерировать заново дизайн-систему для локальной правки.
- Перед завершением UI-правки смотреть отрисованный результат и проверять касания отдельно от мыши и клавиатуры. Проверка только сборки не подтверждает качество интерфейса.

- Поиск открывается из дропдауна «Чат / Задачи» и заменяет поле сообщения **внизу**. Шапка сохраняет своё назначение; дополнительная верхняя строка поиска не нужна. Поле фокусируется в том же нажатии, чтобы открыть клавиатуру.
- Автофокус после мыши/касания не должен рисовать рамку, border, outline или box-shadow поля. Начало набора текста не считается переключением на клавиатурную навигацию. Для Tab-навигации сохранять видимый индикатор.
- Регрессии этих правил проверяет `node tests/browser/team-chat-search.mjs` (Chromium) и тот же запуск с `--webkit`. Обязательные состояния: первое открытие из меню, ввод текста, переход к результату в задаче, возврат, открытая клавиатура и ненулевая safe area. Проверять computed border/outline/box-shadow и положение поля; снимок одного конечного состояния не заменяет эти проверки.
- Время и отметки доставки/прочтения сообщения находятся вместе снизу справа. Исправление повторяющейся визуальной ошибки должно добавлять точечную регрессионную проверку в существующий сценарий.

- Меню после удержания сообщения/задачи принимает действие только после нового отдельного нажатия внутри меню. Отпускание открывающего пальца, совместимый click и смещение пальца на появившуюся кнопку не выбирают действие. Проверять нативное удержание, отпускание над реакцией и следующий намеренный тап.

- Загрузка истории, доставка, фоновая вкладка и закрытый чат не означают прочтение. Подтверждать прочтение только для реально видимой части сообщения в активном окне, без перекрывающего меню/модального окна, и только от другого участника. Проверять отдельными вкладками/контекстами.

- Единая обязательная проверка при изменении интерфейса чата: `npm run test:chat-ui`. Она включает поиск, первичный фокус/ввод, удержание/отпускание и видимость для отметок прочтения в Chromium и WebKit. Не заменять этот запуск только сборкой или количеством unit-тестов.

- В календаре задача чата открывается и редактируется в карточке календаря; переход в рабочий чат выполняется отдельной кнопкой. Изменения относятся к исходной задаче, копии не создавать.
- На смартфоне в сетке месяца только даты и индикаторы, без названий/кнопок задач. Касание даты выбирает день. Список дня получает оставшееся пространство; кнопка добавления не перекрывает строки.
- Фильтры календаря компактные: «Все контрагенты» и «Все сотрудники» внутри полей, без отдельных заголовков; единый шрифт 13px. Проверять это, восстановление удалённых, редактирование без выхода из календаря и экран с 10 задачами через `npm run test:task-calendar` в Chromium и WebKit.

- В обычной карточке календаря даты начала и окончания стоят в одной строке, время начала и окончания — следующей строкой в тех же колонках. Заголовок 16px, дата/время 14px; не возвращать крупный заголовок 22px и отдельную нижнюю строку даты окончания.
- «Удалённые задачи» используют непрозрачный фон из действующей темы и показывают дату/время удаления. Общий диалог обязан иметь запасные цвета для использования вне окна чата.
- Поиск и селекты календаря не получают outline/box-shadow после клика/касания или набора. Для Tab оставлять видимый фокус. `test:calendar-layout` (входит в `test:task-calendar`) проверяет обычную карточку, фокус, непрозрачность и геометрию списка удалённых при 320/390/1280px в обеих темах и движках. Проверка только задач чата и только тёмной темы недостаточна.

- Браузерные сценарии, проверяющие активность окна/прочтение, запускать последовательно с другими браузерными наборами: соседний браузер может перехватить фокус. Ожидания в таких проверках должны иметь ограниченный timeout.

- Даты и время в карточке календаря выравнивать по центру поля, включая внутренний `::-webkit-date-and-time-value`; проверять отрисованный WebKit, а не только координаты input. Описание 14px, компактная высота. Напоминания: 10/30/60 минут и кнопка раскрытия; длительные, точные и повторные — внутри раскрытия, скрытие не стирает значения.
- Внутри задачи один селект статуса вместо трёх текстовых кнопок. У чипов выбора видимая высота 30px при зоне касания 44px; не раздувать обводку ради hit-area. Проверять конфликт общих стилей select (в том числе дублирование стрелок).

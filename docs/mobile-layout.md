# Безопасные области мобильного интерфейса

Фоны, подложки и сама страница остаются до края экрана. Отступ получают элементы: поля ввода, кнопки, панели навигации, футеры и содержимое прокручиваемых форм. Не добавлять общий padding к html, body или #app.

Правило проекта: нижний интерактивный элемент располагается выше системной безопасной области ещё на 12 CSS px. Это выбранный отступ INDEX12, а не универсальное требование Apple в пикселях. Использовать `--safe-bottom-controls` из `src/assets/styles/safe-area.css`; для панели с собственным нижним отступом 12px достаточно добавить `--safe-area-bottom` один раз. Не суммировать safe area повторно у вложенных контейнеров.

Значения `--safe-area-top/right/bottom/left` читаются из `env(safe-area-inset-*, 0px)`. Не фиксировать высоту индикатора Home, не определять её по модели телефона или user-agent. Значения зависят от устройства, ориентации, браузера и режима PWA. Viewport должен содержать `viewport-fit=cover` в обычной странице и HTML входа в чат.

При экранной клавиатуре панели следуют `visualViewport`; у поля над клавиатурой сохраняется обычный отступ 10–12px, без повторного резервирования нижней области устройства. Учитывать верхние и боковые вырезы на самих контролах. Минимальная зона нажатия нижних кнопок INDEX12 — 44×44 CSS px; в нативном Android ориентироваться на 48dp.

Проверять телефон и планшет, портрет/альбом, светлую/тёмную тему, браузер/PWA, клавиатуру открытую/закрытую. В браузерных тестах проверять геометрию с инсетами 0, 20, 34px и боковыми вырезами, используя общие CSS-переменные; это не заменяет проверку на настоящем iPhone/Android. Скриншот Chrome без эмуляции inset не доказывает корректность safe area iPhone.
